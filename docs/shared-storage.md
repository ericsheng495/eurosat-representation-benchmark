    weights/
      base-training/<plan-id>/       best.pt, training metadata, resume state
      torch/                         Official weights/source cache, created on use
    features/                        Model/checkpoint-specific embeddings
    development/                     Development-selection artifacts, when used

`<plan-id>` and `<experiment-id>` are generated by code. Keep them unchanged; names alone cannot identify compatible models. All members point at this same root. Empty cache folders are populated by the existing pipeline, with no new storage service or database.

## Uploading and publishing weights

Upload weights into the matching model folder under `model-uploads/`. Use a descriptive filename such as `resnet18_scratch_seed42_epoch20.pth` so separate runs do not overwrite one another. Include the weight file and a short JSON/text note with architecture, initialization, training classes and class order, seed, epoch, settings, code commit, SHA256, and whether the classifier head is included. This is needed to reconstruct the correct model before loading its state dictionary. For locally produced results, include CSV/JSON metrics and plots. Label whether accuracy is base validation or novel few-shot evaluation, and whether the run is smoke or full.

The model owner verifies the checkpoint and its metadata before publishing it to its compatible cache location and adding a row to RUNS.csv. Uploaded checkpoints are not automatically loaded; the standard pretrained adapters keep using official weights until explicit custom-checkpoint loading is implemented for that model. Keep pretrained, scratch and adapted weights distinct. Do not rename custom weights as an official pretrained checkpoint or overwrite a completed run with different settings.

Coordinate one writer for a given checkpoint, experiment or feature-cache build. Teammates can read completed artifacts concurrently. Drive synchronization is not a distributed lock; Editor access is a permission to modify files, not protection against accidental overwrites.

| Weight artifact | Purpose | Required for evaluating this model? |
|---|---|---|
| best.pt | Selected frozen backbone | Yes |
| completed.json | Checkpoint identity, selection metrics and SHA256 | Yes, for the supplied loader |
| plan.json | Exact training setup and image lineage | Keep for reproducibility |
| last.pt.part001–004 + resume_manifest.json | Current model/head, optimizer and best state for resuming training | No |

Sharing EuroSAT-Team covers these files; no separate per-weight permission is normally needed. Check that teammates can open the checkpoint folder after accepting their invitation.

The selected `best.pt` is one file. The 337 MiB resume state exceeds this connector's 100 MiB upload limit, so it is stored as four parts plus `resume_manifest.json`. This is a connector limit, not a general Google Drive file-size limit. Restore it only when needed:

```sh
cat last.pt.part001 last.pt.part002 last.pt.part003 last.pt.part004 > last.pt
shasum -a 256 last.pt
```

Compare the combined hash with `resume_manifest.json` before loading. Individual part hashes and byte counts are also recorded. Normal checkpoint loading needs only `best.pt` and `completed.json`.

To load the existing MPS-trained weights on Colab without retraining, make the branch's source package available and use:

```python
import json
from pathlib import Path
import torch
from eurosat.training import load_scratch_backbone

folder = Path('/content/drive/MyDrive/EuroSAT-Team/cache/weights/base-training/f5209d5d2030227eb5e7f95c459d24a3c4ce48eccb4afaaa218b58f62157aebe')
artifact = json.loads((folder / 'completed.json').read_text())
artifact['path'] = str(folder / 'best.pt')
model = load_scratch_backbone('dinov2_vits14', torch.device('cuda'), artifact)
```

The loader checks the selected weights' SHA256 and returns a frozen 384-dimensional backbone. Continue to use the shared image preprocessing and L2 embedding normalization. The automatic trainer's plan identity includes device type: launching a fresh CUDA scratch run will not automatically select this MPS training plan. Explicit loading reuses these exact weights across devices; the snippet alone does not run the full evaluation pipeline.
